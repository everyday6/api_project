# 다이어그램 생성 프롬프트

아래 텍스트를 그대로 복사해서 사용하세요.

---

내비게이션 데이터 API 프로젝트를 심사위원에게 설명하기 위한 다이어그램을 그려줘.

## 가장 중요한 메시지 (반드시 시각적으로 강조)

우리 프로젝트는 "최단 경로"나 "최단 시간"을 계산해주는 서비스가 아니다. 우리는
도로망을 segment(구간) 단위로 쪼개서, 각 segment마다 시간/거리/통행료/택시수요
같은 원시 값(raw value)을 만들어 API로 제공할 뿐이다. "어떤 경로가 더 빠른가"를
계산하고 사용자에게 보여주는 건 우리 API를 갖다 쓰는 별도의 내비게이션
서비스(클라이언트)의 역할이다. 처음 보는 사람은 우리를 "최단 시간 구해주는
서비스"로 착각하기 쉬우니, 이 경계를 다이어그램에서 명확히 갈라서 보여줘야 한다.

## 다이어그램 구성 (3단계 흐름, 왼쪽→오른쪽 또는 위→아래)

**1단계 — 데이터 파이프라인 (우리가 하는 일, 사전 작업)**
- Bronze(원본 수집) → Silver(정제/결합) → Gold(segment별 최종 값 계산) 순서의
  간단한 파이프라인 박스 3~4개
- 결과물: "segment_id별 시간/거리/통행료/수요 값"이 DB(DynamoDB)에 쌓인다
- 이 단계 전체를 하나의 그룹으로 묶고 "우리 프로젝트가 만드는 것" 라벨을 붙여줘

**2단계 — 우리 API (우리가 하는 일, 실시간 응답)**
- 파이프라인 결과를 조회하는 API 박스 하나: `POST /api/navigation/values`
- 입력: segment_id 목록 + 타입(시간/거리/통행료/수요)
- 출력: 요청한 segment 각각의 값 목록 (예: [12초, 8초, 15초, ...])
- **중요: 이 API는 여러 개의 segment_id를 받으면 그 개수만큼의 "개별 값 목록"만
  돌려준다. 합산도, 비교도, "어떤 게 더 빠른지" 판단도 절대 하지 않는다는 걸
  화살표나 말풍선으로 명시해줘.**
- **또 중요: 이 segment_id 목록, 즉 "이게 하나의 경로다"라는 정의 자체를 우리가
  만드는 게 아니라는 것도 명시해줘. 어떤 segment들을 묶어서 경로 A/B/C로
  삼을지는 요청을 보내는 쪽(내비게이션 서비스)이 미리 정해서 우리 API에
  넘겨주는 것이고, 우리는 그 목록을 받아서 각 segment의 값만 찾아줄 뿐 그게
  실제로 이어진 경로인지조차 모르고 신경 쓰지도 않는다. "입력값(segment_id
  목록)을 누가 정의하는가"라는 화살표를 3단계 박스에서 2단계 박스로 향하게
  그려서, 경로 정의도 우리 책임이 아니라 요청하는 쪽의 책임이라는 걸 보여줘.**

**3단계 — 내비게이션 서비스 (우리가 안 하는 일, 남의 일)**
- 별도의 박스/영역으로 분리하고 색을 다르게 해서 "우리 프로젝트 바깥"이라는 걸
  시각적으로 확실히 구분해줘 (예: 점선 경계, 다른 배경색, "제3자 서비스" 라벨)
- 이 영역 안에서 일어나는 일:
  1. 후보 경로 A, B, C를 만든다 (각각 segment_id 리스트)
  2. 경로마다 우리 API를 호출해서 segment별 값을 받는다
  3. **여기서 처음으로** 경로별 값을 합산해서 총 시간/총 통행료를 계산한다
  4. 총합을 비교해서 가장 좋은 경로를 골라 사용자에게 "추천 경로"로 보여준다
- 이 3~4번 단계 옆에 "❌ 우리 프로젝트는 여기 관여하지 않음" 같은 명확한
  부정 표시(x 아이콘, 빗금, 경고색 등)를 넣어줘 — 이게 이 다이어그램의 핵심 포인트야

## 스타일 가이드
- 심사위원이 5초 안에 "우리=데이터 제공, 남=경로 계산"이라는 역할 분리를
  이해할 수 있어야 함 — 텍스트는 최소화하고 아이콘/화살표/색 구분 위주로
- 1단계+2단계(우리 영역)는 한 가지 색 계열(예: 파란색 톤), 3단계(남의 영역)는
  확실히 다른 색 계열(예: 회색/주황색 톤)로 구분
- 전체적으로 깔끔한 인포그래픽/플로우차트 스타일, 과도한 장식 없이
- 하단이나 상단에 한 줄 요약 카피 문구를 넣어줘: "우리는 데이터를 만든다.
  경로를 고르는 건 서비스의 몫이다." 같은 톤으로
