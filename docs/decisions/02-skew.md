# 02. [Type3] (zone⋈segment) ⋈ TLC 파티션 스큐

## 문제

(A = zone⋈segment 매핑)

| 항목 | A | TLC |
| --- | --- | --- |
| 데이터 크기 | 약 21.8만 행 | 약 8.8만 행 |
| 파티션 방식 | repartition 200개 | broadcast (파티션 개념 없음) |
| 실제 사용된 파티션 | 141개 / 200개 | - |
| 최대/최소 파티션 크기 비율 | 105배 | - |

- 결과: 일부 작업만 3시간 넘게 걸림

## 원인
- 파티션 기준으로 zone_id 선택
- zone마다 딸린 segment 수는 원래 편차가 큼 (22개~3,435개)
- 결과: 파티션 크기도 그 편차만큼 벌어짐

## 대안

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| zone_id 기준 유지 | 직관적 | 편차 그대로, skew 지속 |
| salting(인위적 분산) | skew 직접 제어 가능 | 이후 단계에 복원 로직 추가 필요 |
| segment_id 기준으로 교체 | 값이 촘촘해서 자연스럽게 고르게 분산 | 완전 균등은 아님 |

## 결정
- 파티션 기준을 segment_id로 교체
- 결과: 최대/최소 편차 105배 → 1.2배
