# 06. 운영 데이터 Publish 완료 기반 ETag 마커 갱신

## 문제

- 다운로드 직후 ETag 마커 갱신
- 후속 Silver 변환·검증·publish 실패 가능성
- 미처리 원천 버전의 처리 완료 오인
- 다음 스케줄에서 실패한 버전의 재처리 누락

## 원인

- 원천 데이터 발견 시점과 처리 완료 시점의 미구분
- 하나의 ETag 마커에 변경 감지와 처리 완료 상태를 함께 저장
- 실제 운영 데이터 반영 전의 이른 마커 갱신

## 대안

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 다운로드 직후 마커 갱신 | 중복 다운로드 감소 | 후속 작업 실패 시 미처리 버전 누락 |
| Bronze 저장 후 마커 갱신 | 원본 파일 확보 보장 | Silver·publish 실패 시 재처리 누락 |
| Publish 성공 후 마커 갱신 | 마커와 운영 데이터 버전 일치 | 실패 시 중복 다운로드 및 재처리 발생 |

## 결과

- Silver 변환·검증과 운영 데이터 publish 성공 후 ETag 마커 갱신
- 중간 실패 시 기존 ETag 마커 유지
- 다음 스케줄에서 실패한 원천 버전 자동 재처리
- 일부 중복 처리 비용을 허용한 데이터 버전 누락 방지
- ETag 마커와 실제 운영 데이터 버전의 일치
