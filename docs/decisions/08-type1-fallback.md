# 08. Type1 폴백 구조

## 문제
- Type1(소요시간)은 실시간 교통 속도 데이터가 5분마다 갱신되지만 결측이 잦고, 신선도가 중요한 지표라 결측이어도 정확한 대체값을 바로 줘야 함
- DynamoDB에서 RDS로 옮기며 멀티 AZ 자동 failover를 잃어, RDS 자체가 응답 불가능한 경우(연결 실패·타임아웃)까지 별도로 대비해야 함

## 원인
- "이 시간대 값이 아직 없음"과 "RDS 자체가 응답 불가능함"은 원인이 다른 별개의 상황
- 같은 폴백 순서에 섞으면 "RDS가 죽어서 대체값을 씀"과 "원래 그 값이 없어서 대체값을 씀"을 모니터링에서 구분할 수 없음

## 대안

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| RDS 값만 쓰고 없거나 실패하면 에러 반환 | 구현 단순 | 결측·장애 시 응답 불가 |
| 하나의 폴백 체인으로 통합 | 구현 단순 | 실패 원인 구분 불가 |
| 상황별로 별도 폴백 체인 운영 | 항상 응답 가능, 원인별 대응·모니터링 가능 | 체인이 두 개로 늘어나 복잡도 증가 |

## 결정
상황별로 폴백 체인을 분리했습니다.

```
[값이 없을 때]
1. Fresh Exact — 오늘 실측값
2. Historical AVG — 그 시간대 과거 평균
3. 코드 상수

[RDS 자체가 응답 불가능할 때]
1. 메모리 캐시
2. S3 Gold 스냅샷
3. 코드 상수
```
