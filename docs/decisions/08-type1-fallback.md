# 08. Type1 폴백 구조

## 문제
- Type1은 실패 상황이 두 가지: "이 시간대 값이 아직 없음"과 "RDS 자체가 응답 불가능함"
- 같은 폴백 순서로 섞으면 둘 중 뭐가 실제로 일어났는지 구분이 안 됨

## 원인
- 값이 없는 건 정상적인 상황(신규·결측 세그먼트)일 수 있어 RDS 장애와 원인이 다름
- 한 체인에 섞으면 "RDS가 죽어서 대체값을 씀"과 "원래 그 값이 없어서 대체값을 씀"을 모니터링에서 구분할 수 없음

## 대안

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 하나의 폴백 체인으로 통합 | 구현 단순 | 실패 원인 구분 불가 |
| 상황별로 별도 폴백 체인 운영 | 원인별 대응·모니터링 가능 | 체인이 두 개로 늘어나 복잡도 증가 |

## 결정
상황별로 폴백 체인을 분리했습니다.

```
[값이 없을 때]
1. Fresh Exact — 오늘 실측값
2. Historical AVG — 그 시간대 과거 평균
3. 코드 상수

[RDS 자체가 응답 불가능할 때]
1. 메모리 캐시
2. S3 Gold 스냅샷
3. 코드 상수
```
