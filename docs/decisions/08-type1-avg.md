# 08. Type1 과거 평균(avg) 설계

## 문제
- 도로 속도 데이터는 5분마다 갱신되지만 결측이 잦아, 오늘 실측값(Fresh Exact)이 없는 슬롯이 자주 생김
- 값이 없다고 코드 상수 하나로 바로 내려가면, 세그먼트·시간대별로 실제 통행시간이 크게 다른데도 전부 같은 값으로 응답하게 됨

## 원인
- 코드 상수는 세그먼트·시간대 특성을 전혀 반영하지 못하는 정성적 초안값
- (segment_id, time) 슬롯별 과거 데이터를 매번 다시 읽어 평균을 내면, 48개 슬롯을 반복 스캔해야 해서 연산이 무거워짐

## 대안

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 값 없으면 바로 코드 상수 | 구현 단순 | 세그먼트·시간대 특성 무시, 부정확 |
| 매번 전체 히스토리 재계산 | 정확한 평균 | 48개 슬롯 반복 스캔, 연산 무거움 |
| 슬롯별 avg를 증분 갱신해 같은 행에 저장 | 조회 한 번으로 끝남, 연산 가벼움 | 정확한 히스토리 재계산은 아님(근사치) |

## 결정
(segment_id, time) 슬롯마다 avg를 증분 공식으로 갱신해서 같은 행에 저장합니다.

```
[슬롯에 첫 값이 들어올 때]
avg = new_value, count = 1

[이미 avg가 있을 때]
count = count + 1                       (기록용 — 상한 없음)
반영비중 = 1 / min(count, 10)            (10 = AVG_SMOOTHING_WINDOW)
avg = avg + (new_value - avg) × 반영비중
```

반영비중을 최근 10회로 상한 둔 이유: count를 그대로 나누면 배치가 수백 번 쌓였을 때 새 값 하나의 영향력이 1/수백로 사라져서, 도로 공사 등으로 실제 통행시간이 바뀌어도 avg가 거의 반응하지 않게 됩니다.

이 avg가 코드 상수보다 실제로 더 정확한지는 별도로 측정하지 않았습니다 — 세그먼트·시간대별 실측 이력을 반영한다는 점에서 상수보다 합리적일 것이라는 도메인 판단에 근거했고, 실측 비교 검증은 남은 과제입니다.
