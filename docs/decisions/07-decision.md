# 07. DAG 간 의존성은 publish 완료 Asset으로 연결한다

## 트리거

Zone–Segment 매핑은 LION 도로망과 Taxi Zone 데이터를 함께 사용합니다.

두 데이터는 서로 다른 DAG에서 처리되기 때문에, 데이터가 준비된 시점에 맞춰 매핑 DAG를 실행할 방법이 필요했습니다.


## 관측된 사실

- LION과 Taxi Zone은 서로 다른 시점에 갱신됩니다.
- 파일 수집이 끝나도 변환이나 검증은 실패할 수 있습니다.
- 따라서 수집 직후 매핑을 시작하면 아직 준비되지 않은 데이터를 읽을 수 있습니다.
- LION이나 Taxi Zone 중 하나가 바뀌면 기존 매핑도 다시 계산해야 합니다.

## 근본 원인

기존에는 데이터가 실제로 준비됐는지가 아니라, 특정 DAG의 실행이 끝났는지를 기준으로 다음 DAG를 실행했습니다.

이 때문에 데이터 처리 과정이 완전히 끝나기 전에 다음 작업이 시작될 수 있었습니다.

## 선택지

고려한 대안들을 나열하고 비교합니다.

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| DAG가 다음 DAG를 직접 실행 | 구현이 단순함 | 데이터 준비 완료 여부를 정확히 알기 어려움 |
| Asset으로 완료 상태 전달 | publish된 데이터만 사용할 수 있음 | Asset 발행 시점을 관리해야 함 |

## 결정

LION과 Taxi Zone DAG는 데이터 변환·검증·publish가 모두 성공한 후에만 Asset을 발행하도록 했습니다.
